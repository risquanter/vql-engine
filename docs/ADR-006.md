# ADR-006: ADT Encoding — `enum` for Pure-Data Sum Types, `sealed trait` for Behavioural Hierarchies

**Status:** Accepted  
**Date:** 2026-04-04  
**Tags:** scala3, adt, imports, coding-style, type-safety

---

## Context

- Scala 3 provides two overlapping mechanisms for closed sum types: `enum` and `sealed trait` + `case class`.
- `sealed trait` + top-level `case class` places variant names directly in the enclosing package namespace, increasing the risk of name collisions and making it impossible to tell at a glance which variants belong together.
- `enum` scopes variants inside the enum's companion, making the grouping structurally explicit and eliminating ambiguity.
- Some sum types carry per-variant abstract behaviour (methods that differ in each case); others carry only data (constructor parameters and no variant-specific logic).
- Mixing the wrong encoding with the wrong intent produces code that is either unnecessarily verbose or unnecessarily flat.
- Inline fully-qualified names scattered through expressions hide a file's dependencies from the import block; import discipline (top-level, named) keeps every dependency reviewable at a glance.

---

## Decision

### 1. `enum` for pure-data sum types

Use `enum` when all variants are distinguished only by constructor parameters — no abstract methods, no per-variant method bodies.

```scala
// GOOD — closed set of data shapes, no per-variant logic
enum TypeDecl:
  case DomainType(id: TypeId)
  case ValueType(id: TypeId)

  def typeId: TypeId = this match  // single shared derivation is fine
    case DomainType(id) => id
    case ValueType(id)  => id

enum TypeCatalogError:
  case UnknownType(name: String, location: String)
  case NameCollision(name: String)
  case FunctionReturnIsDomainType(functionName: String, returnType: String)
```

Variants are accessed as `TypeDecl.DomainType(...)` and `TypeCatalogError.UnknownType(...)`.  
Within the same package, import with `import TypeDecl.*` for short names.  
From other packages, prefer `import vql.typed.TypeDecl.{DomainType, ValueType}`.

### 2. `sealed trait` for behavioural hierarchies

Use `sealed trait` when variants override abstract methods declared on the parent, or when variant bodies are too large to fit cleanly inside an `enum`.

```scala
// GOOD — each variant has unique method implementations
sealed trait VagueQuantifier:
  def toQuantifier: Quantifier
  def describe: String

case class Approximately(target: Double, tolerance: Double = 0.1) extends VagueQuantifier:
  def toQuantifier: Quantifier = Quantifier.mkAbout(...)
  def describe: String = ...

case class AtLeast(threshold: Double, tolerance: Double = 0.0) extends VagueQuantifier:
  def toQuantifier: Quantifier = Quantifier.mkAtLeast(...)
  def describe: String = ...
```

### 3. Derived members in `enum`

When all cases share a logical accessor, declare it as a `def` in the `enum` body using pattern matching. Do not use it as a direct constructor parameter name (avoids name-clash compile errors). This rule governs *derived* accessors — a concrete `def` computed from other fields. An accessor whose value is *stored*, differing per case, is instead an abstract member (`def name: T` with no body) that each case's constructor parameter implements; that is not a name clash and is the correct encoding when the value cannot be derived.

```scala
enum RuntimeModelError:
  case MissingFunctionImplementation(name: SymbolName)
  case MissingPredicateImplementation(name: SymbolName)
  case MissingDomainForType(typeName: TypeId)

  def message: String = this match
    case MissingFunctionImplementation(n)  => s"missing function: ${n.value}"
    case MissingPredicateImplementation(n) => s"missing predicate: ${n.value}"
    case MissingDomainForType(t)           => s"missing domain for type: ${t.value}"
```

### 4. Imports for `enum` variants

Callers within the same package add a local import; callers from other packages use the qualified path or a named import — never open a new wildcard import from a foreign package.

```scala
// Same package
import TypeDecl.*
import TypeCatalogError.*

// Other package
import vql.typed.TypeDecl.{DomainType, ValueType}
import vql.typed.BoundTerm.{ConstRef, LiteralRef}
```

### 5. Top-level imports; no package-qualified names inline

All imports sit at the top of the file, directly after the package clause. Code references a symbol by its simple name via a named import; a package path inline in an expression hides the dependency from the import block.

When a needed name collides with a local definition, import the enclosing object and qualify calls with the object's simple name — never with the package path:

```scala
import util.StringUtil

// local isNumeric shadows StringUtil.isNumeric — qualify via the object
private def isNumeric(s: String): Boolean =
  StringUtil.isNumeric(s) || StringUtil.isDecimalLiteral(s)
```

A method-local import is admissible only to scope an enum-variant wildcard to a single pattern-match-heavy method (e.g. `import Formula.*, Term.*` inside a `ParsedQuery` validation method), keeping variant names out of the rest of the file.

## Code Smells

### ❌ Top-level case classes that form a conceptual group

```scala
// BAD — variants pollute the package namespace; grouping is invisible
sealed trait TypeCatalogError
case class UnknownType(name: String, location: String) extends TypeCatalogError
case class NameCollision(name: String)                 extends TypeCatalogError

// GOOD
enum TypeCatalogError:
  case UnknownType(name: String, location: String)
  case NameCollision(name: String)
```

### ❌ `enum` for types with per-variant abstract behaviour

```scala
// BAD — each case needs distinct method bodies; enum body becomes unwieldy
enum VagueQuantifier:
  case Approximately(target: Double, tolerance: Double)
    def toQuantifier: Quantifier = ...  // not valid in simple enum
  ...

// GOOD — sealed trait lets each case class carry its own implementation
sealed trait VagueQuantifier:
  def toQuantifier: Quantifier
```

### ❌ Accessing enum variants without import or qualification

```scala
// BAD — DomainType looks like a top-level class; reader cannot trace its origin
val t: TypeDecl = DomainType(TypeId("Asset"))

// GOOD
import TypeDecl.*
val t: TypeDecl = DomainType(TypeId("Asset"))    // import visible at file top
// or
val t: TypeDecl = TypeDecl.DomainType(TypeId("Asset"))   // qualified, no import needed
```

### ❌ Package-qualified call instead of an import

```scala
// BAD — dependency invisible in the import block
private def isNumeric(s: String): Boolean =
  util.StringUtil.isNumeric(s) || util.StringUtil.isDecimalLiteral(s)

// GOOD — named import; object-simple-name qualification for the collision
import util.StringUtil
private def isNumeric(s: String): Boolean =
  StringUtil.isNumeric(s) || StringUtil.isDecimalLiteral(s)
```

## Cross-ADR Relationship

ADR-014 uses `TypeDecl` (`DomainType` / `ValueType`) to partition a catalog's declared types into quantifiable and non-quantifiable; `TypeDecl` is a pure-data sum type encoded as `enum` per this ADR. ADR-015 and ADR-016 replace closed literal sums with typeclass boundaries (`LiteralParser[A]`, `Extract[A]`); the IR sum types they leave in place (`BoundTerm`, `BoundFormula`) are pure-data enums per this ADR. ADR-007 C13 governs `enum` refinements inside the OCaml-ported core (e.g. `lexer.Token`); the ported files' wildcard-import style predates this ADR and is preserved under ADR-007. The semantic contracts in ADR-014 and ADR-015 are unaffected by encoding choice.
