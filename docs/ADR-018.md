# ADR-018: Structural Fragment Membership over the Parse Tree

**Status:** Accepted
**Date:** 2026-08-12
**Tags:** fragment, parse-tree, language-boundary, structural-check, validation

---

## Context

- A consumer that admits only a restricted sub-language of FOL must reject an
  out-of-fragment formula at its own input boundary, before the formula reaches
  any sort-checking or evaluation phase, and must know **which** rule was
  violated to report a specific error.
- Membership in such a fragment — "no quantifiers", "no function application",
  "quantifier nesting ≤ k" — is a purely structural property of the parse tree;
  deciding it needs neither a sort catalog nor a runtime model.
- The parser core is a frozen Harrison port (ADR-007): a restricted-grammar
  parser would fork that protected core for no gain. A membership test over the
  tree the existing parser already returns accepts exactly the same string set
  and keeps "reject at the language boundary" intact without touching the parser.
- Quantifier nesting is the cost-relevant structural quantity: each nesting level
  multiplies the domain enumeration an evaluator performs, while side-by-side
  quantifiers only add. A depth budget is therefore the meaningful screening
  knob, and "depth" carries its standard logic meaning (quantifier rank).
- A yes/no answer is insufficient at a validation boundary that emits
  rule-specific errors; a first-violation witness is enough, and reporting every
  offending node is a strictly wider return type that can be added later without
  breaking the narrower one.

## Decision

### 1. `Fragment` and `FragmentViolation` as pure-data sum types

`Fragment` names a sub-language; `FragmentViolation` names a broken rule. Both
are pure-data — no per-variant behaviour — so both are `enum` (ADR-006).

```scala
package vql.fragment

enum Fragment:
  case Targeting                          // no quantifiers, no function-application terms
  case Screening(maxQuantifierDepth: Int) // max quantifier nesting depth ≤ k (0-indexed)

enum FragmentViolation:
  case QuantifierNotAllowed
  case FunctionApplicationNotAllowed(function: String)
  case QuantifierDepthExceeded(limit: Int, found: Int)
```

### 2. `FragmentCheck.check` — a parse-tree walk returning the first violation

`check` walks the inert `Formula[FOL]` and returns `Right(())` iff the formula
lies in the fragment; `Left` carries the first violated rule in pre-order,
left-to-right traversal. It is a top-level object over inert data (ADR-004), takes
no `TypeCatalog` and no `RuntimeModel`, and imports only the foundation.

```scala
object FragmentCheck:
  /** Right(()) iff `formula` lies in `fragment`; Left carries the first
    * violated rule (pre-order, left-to-right). */
  def check(formula: Formula[FOL], fragment: Fragment): Either[FragmentViolation, Unit]
```

### 3. Targeting: no quantifier nodes, no `Term.Fn` terms

`Targeting` rejects any `Formula.Forall`/`Formula.Exists` node
(`QuantifierNotAllowed`) and any `Term.Fn` anywhere in an atom's terms
(`FunctionApplicationNotAllowed`, carrying that function's name). `Term.Const`
(inline literals) and `Term.Var` are admitted. The engine's fixed parse
representation makes this exact: `FOLParser.parse` emits inline literals as
`Term.Const` and every applicative form — `f(args)`, nullary `f()`, unary minus,
and the arithmetic operators `+ - * / ^ ::` — as `Term.Fn`.

### 4. Screening: quantifier rank ≤ k, 0-indexed

`Screening(k)` admits a formula when the largest number of quantifier nodes on any
single root-to-leaf path is ≤ `k`. Siblings do not add; only nesting does.
`Screening(0)` admits no quantifiers (identical to targeting's quantifier rule);
`∃` inside `∃` needs `Screening(2)`. On violation, `QuantifierDepthExceeded.found`
is the formula's actual maximum nesting depth.

```scala
// depth(Forall/Exists p) = 1 + depth(p); depth over a binary node is the max of
// its operands; leaves are 0. Violation iff depth(formula) > k.
```

### 5. Boundary: pre-parsed `Formula[FOL]`, parse error mapped by the caller

`check` takes a parsed formula, never text. A consumer with query text parses via
`FOLParser.parse` (the `Either` boundary, ADR-007 C2) and maps the foundation
`ParseError` at its own boundary — the same input discipline as `satisfyingSet`
(ADR-017 §6). No text parsing and no facade wiring are added; `FragmentCheck` needs
no model, so it is standalone rather than a `VagueSemantics` method.

## Code Smells

### ❌ Forking the parser to restrict the grammar

```scala
// BAD: a second parser that rejects quantifiers duplicates and diverges from
// the frozen Harrison core (ADR-007); it accepts the same strings anyway
object TargetingParser:
  def parse(s: String): Either[ParseError, Formula[FOL]] = /* forked grammar */

// GOOD: parse once with the real parser, then test the tree structurally
FOLParser.parse(s).flatMap(f => FragmentCheck.check(f, Fragment.Targeting).map(_ => f))
```

### ❌ Returning a bare Boolean

```scala
// BAD: the caller cannot emit a rule-specific error
def inFragment(f: Formula[FOL], frag: Fragment): Boolean

// GOOD: the first violated rule is the payload
def check(f: Formula[FOL], frag: Fragment): Either[FragmentViolation, Unit]
```

### ❌ Rejecting inline literals as function applications

```scala
// BAD: treats every non-variable term as a function application; rejects `42`
case Term.Const(_) => Left(FragmentViolation.FunctionApplicationNotAllowed("const"))

// GOOD: only Term.Fn is a function application; Const and Var are admitted
case Term.Fn(name, _) => Left(FragmentViolation.FunctionApplicationNotAllowed(name))
case Term.Const(_) | Term.Var(_) => Right(())
```

### ❌ Counting quantifiers instead of measuring nesting

```scala
// BAD: total quantifier count rejects `∃x.p(x) ∧ ∃y.q(y)` at Screening(1)
val total = countQuantifierNodes(f)

// GOOD: nesting depth (rank) — siblings do not add, only nesting does
val depth = maxQuantifierNesting(f)
```

## Cross-ADR Relationship

- **ADR-007 / ADR-002.** No file in ADR-007's scope tables is touched and no
  characteristic C1–C13 is affected; `FragmentCheck` consumes the parser's output.
  This placement is the direct consequence of ADR-007's preservation mandate.
- **ADR-004.** `vql.fragment` is a vague-layer package importing only the
  foundation `logic.*`; it imports no `vql.typed` and the foundation imports it
  not at all. `FragmentCheck` is an operations object over the inert `Formula`/
  `Term` ADTs.
- **ADR-006.** `Fragment` and `FragmentViolation` are pure-data sums → `enum`.
- **ADR-012.** `check` returns `Either[FragmentViolation, Unit]` as its result
  value (membership-with-reason), not as an operational-failure channel; it needs
  no `require`. `Screening(k)` carries no `k ≥ 0` `require` because `Fragment` is a
  pure-data `enum` (ADR-006) and `check` is total for negative `k` (rejects every
  formula), so no invariant-violation escapes untyped; `k ≥ 0` is documented.
- **ADR-017.** Same pre-parsed-`Formula[FOL]` input boundary and caller-side
  `ParseError` mapping; `FragmentCheck` differs only in needing no model, so it is
  standalone rather than a facade method.
- **ADR-014.** The check is deliberately sort-agnostic; a consumer's sort rule is
  a separate bind-time concern and is not encoded here.

## Alternatives Rejected

### Restricted-grammar parser entry point
- **What:** a second parser that accepts only the fragment's strings.
- **Why rejected:** forks the frozen Harrison-ported core (ADR-007) for no gain;
  a tree walk over the existing parser's output accepts exactly the same set and
  rejects before typed bind, preserving the language-boundary property.

### Bare `Boolean` membership result
- **What:** `inFragment(f, frag): Boolean`.
- **Why rejected:** a validation boundary that emits rule-specific errors needs
  the violated rule; a Boolean discards it and forces the caller to re-derive it.

### `Either[List[FragmentViolation], Unit]` (all offending nodes)
- **What:** collect every violation instead of the first.
- **Why rejected:** membership is yes/no-with-reason; one reason suffices for a
  specific error. Widening to a list later is strictly additive, so it is not
  carried now.

### Total-quantifier-count budget for `Screening`
- **What:** `Screening(k)` bounds the count of quantifier nodes, not nesting.
- **Why rejected:** nesting depth is the cost-relevant quantity (multiplicative)
  and matches the standard meaning of "depth". A count budget, if ever needed, is
  a separate named fragment added additively.
