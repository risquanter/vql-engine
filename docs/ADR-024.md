# ADR-024: Parse Depth Bound

**Status:** Accepted
**Date:** 2026-11-15
**Tags:** parsing, lexer, boundary, stack-safety, consumer-contract

---

## Context

- A thread's stack is fixed. A recursive lexer, parser or tree walk uses
  frames in proportion to its input.
- The size of a frame depends on the JIT state and the platform. The input
  size at which a recursion overflows is therefore not fixed.
- A stack overflow is not a refusal. A boundary that catches only the parsers'
  own failures lets it through, and inside a ZIO effect it ends the process.
- A refusal must not depend on the run. A stored input accepted once must be
  accepted every time it is read back.
- The parser's depth and the parsed tree's depth both follow from the tokens,
  so a bound on the tokens bounds both before any of them run.

---

## Decision

### 1. The lexer is iterative

`Lexer.lex`, `Lexer.lexwhile`, the literal scanner and
`VagueQueryParser.mergeDecimalTokens` loop with an accumulator. Their stack
use is constant in the input's length.

### 2. Both `Either` boundaries check the tokens before parsing

```scala
val tokens = lexer(explode(s))
NestingBound.check(tokens) match
  case Left(failure) => Left(ParseError.Nesting(failure, SourcePosition.Unknown))
  case Right(())     => // parse as before
```

`VagueQueryParser.parse` does the same, and refuses with
`ParseRefusal.Nesting(failure)`. The two `parseTokens` entries run no check.
A caller holding tokens runs `NestingBound.check` first.

### 3. Two counts bound the parse and the tree

- **The parenthesis depth.** Each `(` in formula position costs the parser
  about 20 frames, because the infix-atom attempt parses the bracket as a
  term.
- **Operator tokens and quantified variables.**
  - Every `Not`, connective, infix relation, term operator and unary minus
    comes from one `Token.OpSym`.
  - Every `Forall` and `Exists` comes from one word of a variable list.
  - Nested applications on one path are nested parentheses.

A tree's depth is therefore at most the second count, plus the parenthesis
depth, plus 3.

### 4. The limits are half the smallest measured overflow

```scala
val MaxParenthesisDepth: Int = 64 // smallest measured: 185 levels, interpreted JVM, 1 MiB
val MaxOperators: Int        = 256 // smallest measured: 696 tree levels, evaluation on Node
```

An input within both limits builds a tree at most 323 levels deep.

### 5. A change that adds depth extends the count or is measured

- A grammar construct that adds a tree level without an operator token
  extends `NestingBound`'s count.
- A new recursive walk of the tree is measured against both limits, on a 1 MiB
  interpreted JVM thread and on Node.

## Code Smells

### ❌ Catching the overflow at a boundary

```scala
// BAD: depends on the run, and an overflow inside java.util.regex surfaces as PatternSyntaxException.
catch case _: StackOverflowError => Left(ParseError.Syntax(…))

// GOOD: refuse on the tokens, before anything recurses.
NestingBound.check(tokens)
```

### ❌ A depth counter threaded through the combinators

```scala
// BAD: changes every combinator's shape (ADR-007 C1), and the lexer still overflows.
def parseFormula[A](ifn: AtomParser[A], afn: AtomParser[A])(vs: List[String])(depth: Int)(inp: List[Token])

// GOOD: one pass over the tokens at the boundary.
NestingBound.check(tokens)
```

### ❌ A limit set at the measured edge

```scala
// BAD: a warm JIT parses it, and a cold one overflows.
val MaxParenthesisDepth: Int = 185

// GOOD: half the smallest measurement.
val MaxParenthesisDepth: Int = 64
```

## Cross-ADR Relationship

- **ADR-007.** The bound runs outside every combinator, so C1 and C6 hold. The
  lexer's iterative bodies depart from C10's recursive prepend. Their OCaml
  originals stay in scaladoc under C11. ADR-007's review criterion records the
  departure.
- **ADR-022.** A nesting refusal reports `SourcePosition.Unknown`. No single
  token is at fault, and tokens carry no offset. `NestingFailure` is one of the
  refusal sets.
- **ADR-002 and ADR-012.** The library keeps exactly two `Either` boundaries.
  The check returns a value inside them, and they still catch only the
  parsers' own failures.

## Alternatives Rejected

### A depth counter inside the parser
- **What:** a counter threaded through the combinators, or held in a mutable field.
- **Why rejected:** it breaks ADR-007 C1 or C6. It repeats one check across
  every recursive path. It leaves the lexer and every tree walk unbounded.

### Catching the overflow
- **What:** convert `StackOverflowError` to a refusal at each boundary.
- **Why rejected:** whether an input overflows depends on the run. Near the
  limit, an overflow inside `java.util.regex.Pattern` surfaces as a
  `PatternSyntaxException`. On Scala.js it is a JavaScript `RangeError`.

### A count of all tokens
- **What:** bound the number of tokens in place of operators and quantified
  variables.
- **Why rejected:** a chain of negations adds one tree level per token, so the
  limit would sit near 350. A realistic consumer predicate of 85 disjoined
  atoms holds about 900 tokens and 84 operators.
