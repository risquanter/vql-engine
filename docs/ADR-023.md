# ADR-023: Errors Declared Once above a Shared Identifier Package

**Status:** Accepted
**Date:** 2026-11-12
**Tags:** error-handling, layering, bind-phase, consumer-contract, identity

---

## Context

- The error layer must not depend on the typed layer. A package that both
  layers depend on breaks no direction.
- Sort identity and symbol identity are values both layers need. An error that
  names a sort without the sort's type carries a string the consumer must trust.
- An error declared twice, once with typed fields and once with strings, needs
  a translation between the two. Every new case is then written three times.
- A consumer that receives the same error from two entry points needs the same
  type at both, or it writes two translations.

---

## Decision

### 1. `TypeId` and `SymbolName` live in `vql.id`, which imports nothing

```scala
package vql.id

opaque type TypeId = String
object TypeId:
  def apply(value: String): TypeId =
    require(value.nonEmpty, "TypeId must be non-empty")
    value
  extension (s: TypeId) def value: String = s
```

`vql.typed` keeps the old path through a type alias and a forwarding `apply`:

```scala
type TypeId = vql.id.TypeId
object TypeId:
  def apply(value: String): TypeId = vql.id.TypeId(value)
```

An `export` of the companion is not used. It leaks the underlying `String` to
an inferred call.

### 2. Each error is declared once, in `vql.error`

`TypeCheckError` and `RuntimeModelError` are declared in `vql.error`. Each sort
is a `TypeId` and each catalog symbol a `SymbolName`.

```scala
package vql.error

enum TypeCheckError:
  case TypeMismatch(expected: TypeId, actual: TypeId, site: MismatchSite)
  case UnparseableConstant(name: LiteralText, sort: TypeId, sourceText: LiteralText)
  case TypeNotQuantifiable(sort: TypeId)
  // …

  def message: String = this match
    case TypeNotQuantifiable(sort) => s"type '${sort.value}' is not a domain type and cannot be quantified over"
    // …
```

### 3. A `QueryError` holds the error itself

```scala
case class BindError(details: List[TypeCheckError]) extends QueryError:
  def messages: List[String] = details.map(_.message)

case class ModelValidationError(details: List[RuntimeModelError]) extends QueryError:
  def errors: List[String] = details.map(_.message)
```

`QueryBinder.bind` returns the same `TypeCheckError` values that
`BindError.details` holds. No function translates one into another.

### 4. The import directions

```
vql.id     ← imports nothing
vql.error  ← imports vql.id and the foundation
vql.typed  ← imports vql.error and vql.id
```

## Code Smells

### ❌ A copy of an error with string fields

```scala
// BAD: the second declaration needs a translation, and they drift.
enum BindErrorDetail:
  case TypeNotQuantifiable(name: String, rendered: String)

// GOOD: one declaration, the sort typed.
case TypeNotQuantifiable(sort: TypeId)
```

### ❌ A stored sentence beside the fields

```scala
// BAD: the sentence can disagree with the fields it describes.
case UnparseableConstant(name: String, sortName: String, sourceText: String, rendered: String)

// GOOD: the sentence derives from the fields.
def message: String = this match
  case UnparseableConstant(_, sort, src) => s"cannot parse '${src.value}' as ${sort.value}"
```

### ❌ The error layer importing the typed layer

```scala
// BAD: vql.error and vql.typed then depend on each other.
import vql.typed.TypeId

// GOOD: both import the identifier package.
import vql.id.TypeId
```

### ❌ Exporting an opaque type's companion

```scala
// BAD: SymbolName(x) on an inferred call yields a String.
export vql.id.{SymbolName, TypeId}

// GOOD: an alias and a forwarding apply keep the opaque type.
type SymbolName = vql.id.SymbolName
object SymbolName:
  def apply(value: String): SymbolName = vql.id.SymbolName(value)
```

## Cross-ADR Relationship

- **ADR-004.** The layering holds. `vql.id` sits below `vql.error` and
  `vql.typed`, and `vql.error` imports nothing from `vql.typed`.
- **ADR-019 and ADR-021.** This record supersedes both. The purpose ADR-019's
  context states, "The error layer must not depend on the typed layer", is
  kept. Its rejection of relocating the errors into `vql.error` is overruled.
  The relocation now moves the identifier types below both layers, so it no
  longer inverts the layering.
- **ADR-006.** Each error is a pure-data `enum` with a derived `message`.
- **ADR-020.** The binder's accumulated list is what `BindError` carries.
- **ADR-022.** Every name in a bind error is a `VariableText`, a `SymbolText`
  or a `LiteralText`.

## Implementation

| Location | Pattern |
|---|---|
| `vql/id/Identifiers.scala` | `opaque type TypeId`, `opaque type SymbolName` |
| `vql/typed/TypeDefs.scala` | the aliases and the forwarding companions |
| `vql/error/TypeCheckError.scala` | `TypeCheckError`, `MismatchSite`, `SymbolKind` |
| `vql/error/RuntimeModelError.scala` | `RuntimeModelError` |
| `vql/error/QueryError.scala` | `BindError` and `ModelValidationError` hold the errors; sentences derived |
| `vql/typed/QueryBinder.scala`, `vql/semantics/VagueSemantics.scala` | the binder's list reaches `BindError` unchanged |

---

## Alternatives Rejected

### A primitive-only copy in `vql.error`, translated in the facade
- **What:** ADR-019 and ADR-021: `BindErrorDetail` with string fields and a
  stored sentence, and an exhaustive fold in `VagueSemantics`.
- **Why rejected:** every case is written twice and translated once. A consumer
  that calls the binder directly receives a different type from one that calls
  the facade.

### Re-export the errors from `vql.typed`
- **What:** keep `vql.typed.TypeCheckError` as a second path.
- **Why rejected:** a second path for one type stays in the interface with no
  user once consumers move to `vql.error`.
