# ADR-002: Parser-Combinator Style

**Status:** Accepted  
**Date:** 2026-03-21  
**Tags:** parser, CPS, error-handling, OCaml, combinators

---

## Context

- Parser combinators must compose: a quantifier parser, a variable parser, and a formula parser combine without glue code or intermediate error types
- OCaml's `try/with Failure` pattern gives backtracking for free — each combinator either returns `(result, remaining_tokens)` or throws, and the caller decides whether to retry
- Wrapping every combinator in `Either` forces for-comprehension chains that obscure the grammar and duplicate error-handling at each layer
- The FOL parser core (`Combinators`, `FormulaParser`, `FOLAtomParser`, `Lexer`) uses `List[Token] => (A, List[Token])` — the vague layer must extend this, not reinvent it. `Token` is a Scala-side ADT refinement of the OCaml `string` carrier (ADR-007 C13); the tuple-threading *shape* is what this ADR fixes, independent of the element type
- A parser layered on the foundation invokes those combinators inline and threads their remaining-token list forward; a divergent return convention forces a conversion adapter at every foundation call site
- The foundation combinators select grammar alternatives by exception backtracking — attempt one production, recover on failure to try the next — and are preservation-frozen (ADR-007). A layer returning `Either` internally must still catch and convert those exceptions at each foundation call, reintroducing per-call exception handling rather than eliminating it

---

## Decision

### 1. `ParseResult[A]` as the Universal Return Type

Every parser function — FOL or vague — returns `(A, List[Token])`.
No `Either`, no `Option`, no custom monad inside the parser:

```scala
// parser.Combinators
type ParseResult[A] = (A, List[Token])

// vql.parser.VagueQueryParser — same pattern
def parseTokens(tokens: List[Token]): (ParsedQuery, List[Token]) =
  val (quantifier, t1) = parseQuantifier(tokens)
  val (variable, t2)   = parseVariable(t1)
  val t3               = expect(Token.LParen, t2, "query")
  val (range, t4)      = FormulaParser.parse(...)(t3)  // range is a full FOL formula — see ADR-017
  val t5               = expect(Token.Comma, t4, "query")
  val (scope, t6)      = FormulaParser.parse(...)(t5)
  val t7               = expect(Token.RParen, t6, "query")
  val (answerVars, t8) = parseAnswerVars(t7)
  (ParsedQuery.mk(quantifier, variable, range, scope, answerVars), t8)
```

### 2. Throw on Error, Catch at the Edge

Internal parsers throw `QueryException`. A single `try/catch` at the
public entry point converts to `Either[QueryError, A]`:

```scala
// Public API — one boundary
def parse(s: String): Either[QueryError, ParsedQuery] =
  try
    val tokens = mergeDecimalTokens(Lexer.lex(StringUtil.explode(s)))
    val (query, remaining) = parseTokens(tokens)
    if remaining.nonEmpty then Left(QueryError.ParseError(...))
    else Right(query)
  catch case e: QueryException => Left(e.toError)

// Internal — throws, no Either
private def parseQuantifier(tokens: List[Token]): (Quantifier, List[Token]) =
  tokens match
    case Token.Word("Q") :: Token.LBracket :: op :: Token.RBracket :: rest => ...
    case _ => throw QueryException(QueryError.ParseError(...))
```

### 3. Composition via Token Threading

Combinators compose by passing the remaining token list forward.
Generic infrastructure (`parseLeftInfix`, `parseRightInfix`,
`parseBracketed`, `parseList`) handles precedence and grouping:

```scala
// parser.Combinators — generic infix parsing
def parseRightInfix[A](
  opSym: String, opCons: (A, A) => A,
  subParser: List[Token] => ParseResult[A]
)(inp: List[Token]): ParseResult[A] =
  val (left, rest) = subParser(inp)
  if nextin(rest, opSym) then
    val (right, rest2) = parseRightInfix(opSym, opCons, subParser)(rest.tail)
    (opCons(left, right), rest2)
  else (left, rest)
```

### 4. Lexer Produces Flat Token List

`Lexer.lex` tokenizes the character list into `List[Token]`.
All parsers operate on this flat list — no intermediate AST,
no position tracking beyond the list itself. `Token` is an `enum`
(ADR-006) refining the OCaml `string` carrier (ADR-007 C13); each case
records the OCaml string it replaces:

```scala
// lexer.Lexer
def lex(input: List[Char]): List[Token]

// lexer.Token — Word/OpSym/StringLit carry a String; the rest are punctuation
enum Token:
  case Word(name: String)      // "Q", "3", "country"
  case OpSym(sym: String)      // ">=", "/\\", "==>"
  case StringLit(content: String)
  case LParen, RParen, LBracket, RBracket, LBrace, RBrace, Comma, Dot
```

## Code Smells

### ❌ Either Inside Combinators

```scala
// BAD: Each combinator returns Either, requiring for-comprehension
def parseTokensInternal(tokens: List[Token]): Either[QueryError, (ParsedQuery, List[Token])] =
  for
    (quantifier, t1) <- parseQuantifierInternal(tokens)
    (variable, t2)   <- parseVariableInternal(t1)
    ...
  yield (query, remaining)

// GOOD: Combinators return tuples, throw on failure
def parseTokens(tokens: List[Token]): (ParsedQuery, List[Token]) =
  val (quantifier, t1) = parseQuantifier(tokens)
  val (variable, t2)   = parseVariable(t1)
  ...
  (query, remaining)
```

### ❌ Wrapper Pairs (*Internal + throwing)

```scala
// BAD: Two methods for the same operation
def parseQuantifierInternal(tokens: List[Token]): Either[QueryError, ...]
def parseQuantifier(tokens: List[Token]): (Quantifier, List[Token]) =
  parseQuantifierInternal(tokens).fold(e => throw ..., identity)

// GOOD: One method, one style
def parseQuantifier(tokens: List[Token]): (Quantifier, List[Token]) =
  tokens match
    case Token.Word("Q") :: ... => ...
    case _ => throw QueryException(...)
```

### ❌ Re-wrapping Exceptions Mid-Flight

```scala
// BAD: Catch exception from layer below, wrap in Either, then caller unwraps
def parseFormulaSafe(tokens: List[Token]): Either[QueryError, ...] =
  try Right(FormulaParser.parse(...)(tokens))
  catch case e: Exception => Left(QueryError.ParseError(e.getMessage, ...))

// GOOD: Let exceptions propagate, catch once at the edge
val (scope, t6) = FormulaParser.parse(...)(t5)  // throws propagate naturally
```

## Cross-ADR Relationship

**ADR-007 (OCaml-ported core preservation).** ADR-007 freezes the foundation
parsers (`Combinators`, `FormulaParser`, `FOLAtomParser`, `TermParser`,
`FOLParser`, `Lexer`) as ports that select grammar alternatives by exception
backtracking. This ADR governs `vql.parser.VagueQueryParser`, which is not a
port but is layered directly on those parsers. `VagueQueryParser` inherits the
throw-internally / convert-at-the-edge discipline not for stylistic
consistency alone but because it composes with the frozen exception-based
foundation: returning `Either` inside its combinators would force a
catch-and-convert at every call into the foundation (the "Re-wrapping
Exceptions Mid-Flight" smell above), which the frozen foundation makes
unavoidable. The single `Either` boundary for a vague query therefore sits at
`VagueQueryParser.parse`.

## Implementation

| Location | Pattern |
|---|---|
| `parser/Combinators.scala` | `ParseResult[A] = (A, List[Token])` type, generic infix/bracket/list combinators |
| `parser/FormulaParser.scala` | FOL formula parsing via combinator composition |
| `parser/FOLAtomParser.scala` | Atom/term parsing — throws on malformed input |
| `lexer/Lexer.scala` | `List[Char] → List[Token]` tokenization |
| `lexer/Token.scala` | `Token` ADT (ADR-006 `enum`, ADR-007 C13 refinement) |
| `vql/parser/VagueQueryParser.parse()` | Single `try/catch → Either` boundary |
| `vql/parser/VagueQueryParser.parseTokens()` | Vague query combinator — extends FOL parsers |
