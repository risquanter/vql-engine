# ADR-021: Structured Bind-Error Detail for Every `TypeCheckError` Variant

**Status:** Accepted
**Date:** 2026-08-31
**Tags:** error-handling, layering, bind-phase, boundary, consumer-contract

---

## Context

- ADR-019 introduced `BindErrorDetail` in `vql.error` to carry a bind error's
  sort across the error/typed boundary as a primitive. It gave one structured
  case, `UnparseableConstant`, the sort name it needs; every other
  `TypeCheckError` variant folded to a single `Other(rendered)` case that keeps
  only the rendered string.
- That left the projection asymmetric: 1 of the 11 `TypeCheckError` variants
  carried its fields as data, and the other 10 discarded them. ADR-019's own
  "Discarding the sort at the render step" smell — losing a datum a consumer
  would otherwise re-derive out of band — applied to those ten as much as to the
  one it fixed. A consumer wanting the mismatched sorts of a `TypeMismatch`, the
  arity numbers of an `ArityMismatch`, or the variable name of an
  `UnconstrainedVar` had to parse the rendered string, the exact re-derivation
  the structured detail exists to remove.
- The `Other` catch-all also made the facade fold non-exhaustive: it matched
  `UnparseableConstant` and sent everything else to `Other` through a wildcard.
  A new `TypeCheckError` variant would compile silently and land in `Other`,
  losing its fields with no signal.
- ADR-020 then made `BindError.details` a genuinely multi-element list (the
  binder accumulates across independent subtrees). With more than one detail per
  failure now normal, the value of each detail carrying its own fields rather
  than a flattened string rose accordingly.

---

## Decision

### 1. One `BindErrorDetail` case per `TypeCheckError` variant

`BindErrorDetail` gains a case for each of the 11 `TypeCheckError` variants,
each holding that variant's fields as primitives plus its `rendered` string. The
`Other` catch-all is removed.

```scala
package vql.error

enum BindErrorDetail:
  case UnparseableConstant(name: String, sortName: String, sourceText: String, rendered: String)
  case TypeMismatch(expectedSort: String, actualSort: String, context: String, rendered: String)
  case ConflictingTypes(name: String, leftSort: String, rightSort: String, rendered: String)
  case ArityMismatch(symbol: String, expected: Int, actual: Int, rendered: String)
  case UnknownPredicate(name: String, rendered: String)
  case UnknownFunction(name: String, rendered: String)
  case UnknownConstantOrLiteral(name: String, rendered: String)
  case UnboundAnswerVar(name: String, rendered: String)
  case UnconstrainedVar(name: String, rendered: String)
  case TypeNotQuantifiable(name: String, rendered: String)
  case UnexpectedFreeVar(name: String, rendered: String)

  def rendered: String
```

A `TypeId` still crosses as its `TypeId.value` `String` (ADR-015); every field
is a primitive, so `vql.error` still imports nothing from `vql.typed` (ADR-004).

### 2. The facade fold is exhaustive with no catch-all

`toBindErrorDetail` in `vql.semantics` matches all 11 `TypeCheckError` variants
by name and has no wildcard arm. Adding a 12th `TypeCheckError` variant is a
compile error here until a matching `BindErrorDetail` case and fold arm exist —
the projection cannot silently drop a variant's fields.

```scala
private def toBindErrorDetail(error: TypeCheckError): BindErrorDetail =
  import BindErrorDetail as D
  val rendered = renderTypeError(error)
  error match
    case TypeCheckError.UnparseableConstant(name, sort, src) => D.UnparseableConstant(name, sort.value, src, rendered)
    case TypeCheckError.TypeMismatch(exp, act, ctx)          => D.TypeMismatch(exp.value, act.value, ctx, rendered)
    // … one arm per variant, no `case _` …
```

### 3. `renderTypeError` is unchanged — no string drift

The single per-error renderer (ADR-019 §3) already covered all 11 variants and
is untouched. Each detail's `rendered`, and therefore `BindError.messages` and
`message`, is byte-identical to before. A text-only consumer sees no change.

## Code Smells

### ❌ A catch-all that flattens fields

```scala
// BAD: 10 of 11 variants lose their fields; a new variant lands here silently.
error match
  case TypeCheckError.UnparseableConstant(n, s, t) => D.UnparseableConstant(n, s.value, t, rendered)
  case _                                           => D.Other(rendered)

// GOOD: one arm per variant, no wildcard — a new variant fails to compile here.
error match
  case TypeCheckError.UnparseableConstant(n, s, t) => D.UnparseableConstant(n, s.value, t, rendered)
  case TypeCheckError.TypeMismatch(e, a, c)        => D.TypeMismatch(e.value, a.value, c, rendered)
  /* … all 11 … */
```

### ❌ Re-deriving a field from the rendered string

```scala
// BAD: the consumer parses the arity numbers back out of the message text.
val n = raw"expected (\d+), actual (\d+)".r.findFirstMatchIn(detail.rendered)

// GOOD: read the fields the detail carries.
detail match { case a: BindErrorDetail.ArityMismatch => (a.expected, a.actual) }
```

## Cross-ADR Relationship

- **ADR-004.** Preserved: every `BindErrorDetail` field is a primitive and the
  fold runs in the facade, the layer that already imports both sides. No import
  direction changes.
- **ADR-006.** `BindErrorDetail` stays a pure-data `enum` sharing the abstract
  `rendered` accessor; the case parameters implement it (a concrete derived
  `def rendered` would clash — ADR-006 §3).
- **ADR-012.** `BindError` stays on the `Either` left channel; only the detail
  cases change.
- **ADR-015.** A sort still crosses as `TypeId.value`; the enrichment adds more
  primitive fields, no new carrier and no `asInstanceOf`.
- **ADR-019.** This extends ADR-019's decision from the one `UnparseableConstant`
  case to all 11 variants and drops the `Other` catch-all. ADR-019's E3
  (relocate `TypeCheckError`/`TypeId` into `vql.error`) stays rejected — the
  boundary is still crossed with primitives, not typed values.
- **ADR-020.** The multi-element `details` list ADR-020 fills now carries a
  structured, per-variant detail for each accumulated error.

## Implementation

| Location | Pattern |
|---|---|
| `vql/error/QueryError.scala` | `enum BindErrorDetail` — 11 cases, one per `TypeCheckError` variant; no `Other` |
| `vql/semantics/VagueSemantics.scala` | `toBindErrorDetail` — exhaustive 11-arm fold, no wildcard; `renderTypeError` unchanged |
| `vql/semantics/VagueSemanticsTypedSpec.scala` | per-variant structured projection (`ArityMismatch`, `ConflictingTypes`); `rendered`/`messages` byte-identical |

## Alternatives Rejected

### Keep `Other` for the non-sort-bearing variants
- **What:** give `UnparseableConstant` and the other sort-bearing errors
  structured cases, but leave the plain `name`-only variants folding to `Other`.
- **Why rejected:** it keeps the fold non-exhaustive (the wildcard stays), so a
  new `TypeCheckError` variant still lands in `Other` silently. It also keeps the
  asymmetry ADR-019's own smell warns against for the very fields — a variable
  name, an arity pair — a consumer would otherwise parse back out of the string.
  A case per variant costs one line each and removes both problems.

### E3 (from ADR-019) — relocate `TypeCheckError`/`TypeId` into `vql.error`
- **What:** move the typed error and sort types down so `BindError` carries
  `List[TypeCheckError]` directly.
- **Why rejected:** unchanged from ADR-019. It inverts the ADR-004 layering by
  making the low, stable error vocabulary depend on the type system. This ADR
  gets every field a consumer needs across the boundary as primitives, so the
  relocation buys nothing it does not already have.
