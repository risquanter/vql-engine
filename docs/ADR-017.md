# ADR-017: Formula Ranges and the Satisfying-Set Boundary

**Status:** Proposed
**Date:** 2026-08-10
**Tags:** typed-IL, query-binding, range-semantics, closed-world, satisfying-set, many-sorted

---

## Context

- A vague query has the form `Q x (R(x, y'), φ(x, y))` (ADR-001, paper
  Definition 1). The range `R(x, y')` selects the population `D_R` the
  quantifier ranges over; the scope `φ(x, y)` is the property whose proportion
  over `D_R` is estimated. Until now the range was a single positive atom: one
  predicate applied to the quantified variable and answer variables.
- A single-atom range cannot express a compound population — "servers that are
  internet-facing **and not** patched", "assets that are `p95`-above a
  threshold **or** flagged". Expressing these requires the range to be a full
  FOL formula (conjunction, disjunction, negation, inner quantifiers), not one
  atom.
- Negation in a range is only meaningful against a finite enumerated
  population. `¬patched(x)` means "the elements of the active domain for which
  `patched` does not hold" — a complement taken over the registered element set
  of the variable's sort, not over an open or infinite universe. This is a
  closed-world reading and it is sound only because range extraction enumerates
  the full active domain exactly (never sampled).
- Separately, consumers need to evaluate a bare formula with one free variable
  to its exact satisfying set over that variable's sort — with no quantifier, no
  answer variables, and no proportion estimate. This is a distinct entry point
  from vague-query evaluation and returns a set, not a `VagueQueryResult`.

---

## Decision

### 1. Range semantics: a formula, extracted exactly over the active domain

The range of a vague query is a full FOL formula. For quantified variable `x`
of sort `S` (a domain type), the range population is

```
D_R = { d ∈ domain(S) | evalFormula(range, baseEnv + (x → d)) == true }
```

where `domain(S)` is the active domain — the registered element set
`model.domains(S)` — and `baseEnv` binds the answer variables. Extraction
enumerates every element of `domain(S)` and keeps those the range formula
accepts.

The formula connectives compose set-theoretically over `domain(S)`:

- `And(φ, ψ)` → `D_φ ∩ D_ψ`
- `Or(φ, ψ)` → `D_φ ∪ D_ψ`
- `Not(φ)` → `domain(S) \ D_φ` (closed-world complement over the active domain)
- `Imp` / `Iff` follow from `evalFormula` per element
- an inner range quantifier (`Exists(a: T, r(x, a))`) ranges over `domain(T)`
  at each candidate `d`, reusing the evaluator's quantifier cases

A single-atom range `R(x, y')` is the special case `Atom(R(x, y'))`, whose
extraction is identical to the previous atom-only path (AC-3, byte-identical
results).

### 2. Closed-world negation soundness invariant

`Not(φ)` over a range is the complement of `D_φ` within `domain(S)`. This is
sound **only** because range extraction is exact full enumeration of
`domain(S)` and is never sampled. Sampling applies only to scope evaluation
inside `evaluateOverRange` (ADR-003 §3: "exact" is the degenerate case of
"sampled"); it is never applied to `collectRangeElements`.

> Invariant: if range extraction were ever sampled, `domain(S) \ D_φ` would be
> computed against a partial `D_φ` and the complement would be wrong. Range
> extraction stays exhaustive. See ADR-003 (sampling scope) and the AC-6 pin.

### 3. Denominator is the compound population

The proportion's denominator is `|D_R|` — the size of the compound satisfying
set, not `|domain(S)|`. `EvaluationOutput.result.domainSize` and
`EvaluationOutput.rangeElements` both report `D_R` (AC-2). This is already how
`evaluateOverRange` computes the estimate (it uses `rangeElements.size`); with
a formula range, `D_R` is the compound set rather than the atom's extension.

### 4. Range validation over free variables

Two validation rules govern a range formula, restated over **free** variables
(`FOLUtil.fvFOL`) so that inner range quantifiers bind their own variables
correctly:

1. The quantified variable must occur free in the range: `x ∈ fvFOL(range)`.
   A range like `exists x . p(x)` (which binds `x`) or `p(y)` (which omits `x`)
   is rejected.
2. Every other free range variable must be an answer variable:
   `fvFOL(range) \ {x} ⊆ answerVars`. This is the paper's `y' ⊆ y` constraint
   expressed over free variables.

Rule enforcement is layered:

- `ParsedQuery.mk` enforces both rules at the surface (throw-at-edge, behind
  `VagueQueryParser.parse`'s `Either` boundary — ADR-002, D-1 ruling).
- `QueryBinder.bind` independently requires the quantified variable to receive
  a sort during range binding (`UnconstrainedVar` otherwise) and that sort to
  be a domain type (`TypeNotQuantifiable`, ADR-014). These bind-time checks
  operate on the environment produced by binding the range formula.

### 5. Typed IL: `BoundQuery.range` widens to `BoundFormula`

```scala
case class BoundQuery(
  quantifier: Quantifier,
  variable: BoundVar,
  range: BoundFormula,   // was BoundAtom — now a sort-checked range formula
  scope: BoundFormula,
  answerVars: List[BoundVar] = Nil
)
```

`QueryBinder.bind` binds the range with `bindFormula(query.range, Map.empty,
catalog)` — the same binder the scope already uses, which performs cross-atom
sort unification via `mergeEnvs` and returns `ConflictingTypes` on
disagreement (AC-4, existing machinery). `TypedSemantics.collectRangeElements`
evaluates the range with `evalFormula` instead of `evalAtom`. A single-atom
range binds to `BoundFormula.Atom`, whose `evalFormula` case delegates to
`evalAtom` — the previous behavior exactly.

### 6. Satisfying-set contract

A public entry point evaluates a bare formula with one free variable to its
exact satisfying set:

```
satisfyingSet(φ, v, model) =
  { d ∈ domain(sort(v)) | evalFormula(φ, { v → d }) == true }
```

Contract:

- **Exact and deterministic.** Enumerates `model.domains(sort(v))` and filters
  with the existing `evalFormula`; no sampling parameters exist on this API.
  Two evaluations of the same inputs produce equal sets.
- **Type-checked.** `φ` is bound from an empty environment. The bound formula's
  free variables must equal exactly `{v}`; a free variable other than `v`, or
  `v` absent, is rejected with a new `TypeCheckError` variant for an unexpected
  free variable (encoded per the existing `TypeCheckError` enum, ADR-006). The
  sort inferred for `v` must be a domain type (`TypeNotQuantifiable`, ADR-014) —
  this check is replicated here because `satisfyingSet` enumerates `v`'s domain
  outside `QueryBinder.bind`.
- **`Either`-returning.** `List[TypeCheckError]` at the binder; `QueryError` at
  the `VagueSemantics` facade.
- **Input is a pre-parsed `Formula[FOL]`.** No text parsing inside this entry.
  Callers with text parse it via `FOLParser.parse` (Phase 1 `Either` boundary,
  ADR-007 C2) and map the foundation parse error at their own boundary; no
  vague-layer parse wrapper is added.

### 7. Consequence notes

- Range extraction may now invoke dispatcher **predicates and functions** for
  every atom in the range formula. Previously only the single range predicate's
  `evalAtom` ran per candidate; `evalFormula` walks every atom, each resolving
  through `RuntimeDispatcher.evalPredicate` / `evalFunction`. No new dispatcher
  surface is added.
- The T-002 named-constant interim (a `ConstRef` is projected as its raw
  carrier until a dedicated `evalConstant` lands on `RuntimeDispatcher`) applies
  inside ranges exactly as it does inside scopes. A range formula containing a
  named constant resolves it the same way the scope does.

## Code Smells

### ❌ Sampling range extraction

```scala
// BAD: sampling the range makes closed-world negation unsound —
// domain(S) \ D_φ computed against a partial D_φ is wrong
val sampled = sampler.sample(rootDomain, n)
collectRangeElements(query, model, baseEnv, sampled)

// GOOD: range extraction is exhaustive; sampling applies only to scope
collectRangeElements(query, model, baseEnv, rootDomain)   // full active domain
```

### ❌ Passing raw text to `satisfyingSet`

```scala
// BAD: satisfyingSet takes a parsed formula, not a string
satisfyingSet("~patched(x)", "x", model)   // does not compile

// GOOD: parse at the FOLParser boundary, map the parse error, then evaluate
FOLParser.parse("~patched(x)")
  .left.map(e => QueryError.ValidationError(e.message, "formula"))
  .flatMap(satisfyingSet(_, "x", model))
```

## Cross-ADR Relationship

- **ADR-001 §3** codifies `BoundQuery` with `range: BoundAtom` ("sort-checked
  range predicate"). This ADR widens it to `range: BoundFormula`. ADR-001 §3
  receives a consistency edit and a cross-reference to this ADR in Phase 6;
  ADR-001 §§1–2 (the `TypeCatalog` contract and the `bind` compilation step)
  are unchanged.
- **ADR-002 / ADR-007.** The range production reuses
  `FormulaParser.parse(parseInfixAtom, parseAtom)` — the exact combinator stack
  the scope already uses. No file in ADR-007's scope tables is modified and no
  characteristic C1–C13 is touched. Grammar termination is sound without core
  changes: `,` is not an infix operator, so the formula parser stops before the
  range/scope comma; commas inside atom argument lists are consumed within the
  atom parser's parentheses.
- **ADR-003.** Closed-world negation is sound only under exact full enumeration
  of the active domain (§2 invariant). Sampling stays confined to scope
  evaluation.
- **ADR-012.** The `satisfyingSet` facade returns `Either[QueryError, A]`; its
  text-parse feed is the `FOLParser.parse` `Either` boundary (Phase 1). No new
  throwing surface is introduced.
- **ADR-014.** `satisfyingSet` replicates the domain-type quantifiability check
  for its variable because it enumerates that variable's domain outside
  `QueryBinder.bind`.
- **ADR-015 / ADR-016.** Range atoms carry inline literals, named constants,
  and function applications through the existing `LiteralRef` / `ConstRef` /
  `FnApp` binder branches and `Extract[A]` boundaries unchanged.
