# ADR-004: Tagless Initial Architecture

**Status:** Accepted  
**Date:** 2026-03-21  
**Tags:** architecture, tagless-initial, ADT, OCaml, separation-of-concerns

---

## Context

- A logic engine operates on recursive tree structures (formulas, terms, queries) that benefit from exhaustive pattern matching — adding new operations must not require modifying the data types
- OCaml's module system separates types from functions — a Scala port preserving this separation avoids coupling data layout to operation sets
- OO-style methods on data types conflate "what the data is" with "what can be done to it" — printing, evaluation, optimization, and serialization are independent concerns that evolve at different rates
- The FOL foundation must be reusable independently of the vague quantifier extension — layering requires that the extension imports the foundation, not the other way around

---

## Decision

### 1. ADTs for Data, Objects for Operations

Data structures are enums and case classes. Operations live in
companion-free top-level objects. No methods on data types beyond
structural accessors:

```scala
// logic/Formula.scala — data only
enum Formula[A]:
  case Atom(a: A)
  case Not(f: Formula[A])
  case And(f: Formula[A], g: Formula[A])
  case Or(f: Formula[A], g: Formula[A])
  case Imp(f: Formula[A], g: Formula[A])
  case Iff(f: Formula[A], g: Formula[A])
  case Forall(x: String, f: Formula[A])
  case Exists(x: String, f: Formula[A])

// semantics/FOLSemantics.scala — operations
object FOLSemantics:
  def holds[D](formula: Formula[FOL], model: Model[D], valuation: Valuation[D]): Boolean

// printer/FOLPrinter.scala — separate operation
object FOLPrinter:
  def printFormula(formula: Formula[FOL], prec: Int = 0): String
```

### 2. Two-Layer Architecture: FOL Foundation + Vague Extension

The FOL layer (`logic/`, `parser/`, `semantics/`, `printer/`, `lexer/`)
provides general-purpose first-order logic. The vague layer (`vql/`)
extends it with probabilistic quantifiers. The vague layer imports FOL;
FOL never imports vague:

```
┌──────────────────────────────────────────────────────┐
│  vql/  (vague quantifier extension)                  │
│  ├── parser/     VagueQueryParser                    │
│  ├── typed/      TypeCatalog, QueryBinder, BoundQuery,│
│  │               TypedSemantics, RuntimeModel,        │
│  │               RuntimeDispatcher, FolModel, Extract │
│  ├── semantics/  VagueSemantics (typed facade)       │
│  ├── sampling/   HDRSampler, ProportionEstimator     │
│  ├── fragment/   Fragment, FragmentViolation,         │
│  │               FragmentCheck                        │
│  ├── logic/      ParsedQuery                          │
│  ├── result/     VagueQueryResult, EvaluationOutput  │
│  ├── error/      QueryError, QueryException          │
│  └── quantifier/ VagueQuantifier, Quantifier         │
├──────────────────────────────────────────────────────┤
│  Foundation (pure FOL — no vague imports)             │
│  ├── logic/      Formula, Term, FOL, Model           │
│  ├── parser/     Combinators, FormulaParser,         │
│  │               FOLAtomParser, TermParser, FOLParser │
│  ├── lexer/      Lexer, Token                        │
│  ├── semantics/  FOLSemantics                        │
│  └── printer/    FOLPrinter, PrinterUtil             │
└──────────────────────────────────────────────────────┘
```

### 3. Typed Evaluation Pipeline in the Vague Layer

The vague layer evaluates through the many-sorted typed pipeline (ADR-001),
preserving the ADT-for-data / objects-for-operations discipline:

- `TypeCatalog` declares sorts and symbol signatures; `QueryBinder.bind`
  type-checks a `ParsedQuery` against it into a `BoundQuery` (the typed IL).
- `RuntimeModel` supplies each sort's domain and a `RuntimeDispatcher` that
  decides predicates and functions; `FolModel` validates a catalog/model pair.
- `TypedSemantics.evaluate` interprets a `BoundQuery` against a `RuntimeModel`,
  threading an environment (variable → `Value`) through the recursive
  `evalFormula` — the operation stays a top-level object over inert data.

```scala
// vql/typed — BoundQuery is inert data; evaluation is a separate object
object TypedSemantics:
  def evaluate(
    query: BoundQuery, model: RuntimeModel, ...
  ): Either[QueryError, EvaluationOutput[Value]]
```

## Code Smells

### ❌ Methods on Data Types

```scala
// BAD: Operation coupled to data
enum Formula[A]:
  case And(f: Formula[A], g: Formula[A]):
    def holds(model: Model[Any]): Boolean = ...  // printing, optimization also here?

// GOOD: Data is inert, operations are separate
enum Formula[A]:
  case And(f: Formula[A], g: Formula[A])

object FOLSemantics:
  def holds[D](formula: Formula[FOL], model: Model[D], valuation: Valuation[D]): Boolean =
    formula match
      case And(f, g) => holds(f, model, valuation) && holds(g, model, valuation)
```

### ❌ Vague Layer Leaking into FOL

```scala
// BAD: the foundation FOL layer knows about vague quantifiers
object FOLSemantics:
  def holdsVague(query: ParsedQuery, model: RuntimeModel): Boolean = ...

// GOOD: the vague layer (vql.typed) builds on the foundation, never the reverse
object TypedSemantics:
  def evaluate(query: BoundQuery, model: RuntimeModel, ...): Either[QueryError, EvaluationOutput[Value]] =
    ... // uses the foundation's Formula/Term ADTs; the foundation never imports vql.*
```

### ❌ Scattered Type Conversions

```scala
// BAD: manual raw-carrier conversion duplicated across dispatcher lambdas
val loss: Long = value.raw match
  case l: Long   => l
  case s: String => s.toLong
  case other     => sys.error(s"bad carrier: $other")

// GOOD: recover the typed view through the Extract[A] boundary (ADR-015 §2)
val loss: Either[String, Long] = value.extract[Long]
```

## Implementation

| Location | Pattern |
|---|---|
| `logic/Formula.scala`, `logic/Term.scala` | Pure ADTs — no methods beyond accessors |
| `semantics/FOLSemantics.holds()` | Tarski evaluation via pattern matching |
| `printer/FOLPrinter.printFormula()` | Precedence-aware printing (uses `PrinterUtil`) |
| `vql/typed/QueryBinder.bind` | `ParsedQuery` → typed `BoundQuery` (ADR-001) |
| `vql/typed/TypedSemantics.evaluate` | Interprets `BoundQuery` against `RuntimeModel` |
| `vql/semantics/VagueSemantics` | Typed facade: parse-bound query → evaluation |
